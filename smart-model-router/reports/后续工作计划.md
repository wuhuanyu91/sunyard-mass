# MAS 平台后续工作计划

> 基于后端 API 58 个端点全部通过集成测试（100% 通过率）后的后续规划

## 一、当前状态总结

| 维度 | 现状 |
|------|------|
| **后端 API** | 58 个端点全部通过集成测试，覆盖 Dashboard/Metering/Routing/ModelAsset/Security/Cache/ApiKey 共 7 个模块 |
| **后端数据层** | 仅 3 个 Service 使用真实 DB 查询（ApiKeyService、MeteringService.listCallLogs、ModelAssetService.listModelAssets）；其余全部返回硬编码 mock 数据 |
| **数据库** | 8 张表，种子数据有限 |
| **前端** | api.ts 约 100+ 方法，全部通过 `mock()` 函数包装本地静态数据；vite proxy 已配好 |
| **契约覆盖缺口** | 前端 api.ts 约 40-50 个方法尚无后端端点（系统管理、K8s、成员权限、审批、批量任务等） |

---

## 二、工作计划（按优先级排序）

### P0 — 前端对接后端真实 API（最高优先级，7 人天）

**目标**: 将前端 api.ts 从 mock 切换到真实后端调用，实现端到端数据流通。

#### 阶段 1: 基础设施层（1 人天）

| 任务 | 验收标准 |
|------|----------|
| 创建 `src/services/http.ts`，封装 fetch 基础函数，处理 base URL `/smart-router`、错误统一格式 | 网络错误/4xx/5xx 统一抛出含 code 的 Error |
| snake_case/camelCase 自动转换（后端 `asset_id` ↔ 前端 `assetId`） | 前端组件无需修改字段名 |
| `api.ts` 增加 `USE_MOCK` 全局开关（按模块粒度） | `{ dashboard: false, metering: true, ... }` 格式 |

#### 阶段 2: 逐模块对接（5 人天）

| 优先级 | 模块 | 前端方法数 | 工作量 |
|--------|------|-----------|--------|
| 2a | Metering（计量运营） | ~10 | 1 天 |
| 2b | Dashboard（驾驶舱） | ~14 | 1 天 |
| 2c | Routing（路由配置） | ~14 | 1 天 |
| 2d | ModelAsset（模型资产） | ~9 | 0.5 天 |
| 2e | Security（安全审计） | ~9 | 0.5 天 |
| 2f | ApiKey + Cache | ~5 | 0.5 天 |
| 2g | 联调与回归 | - | 0.5 天 |

#### 阶段 3: 前端适配调整（1 人天）

- 分页参数对齐（后端返回 `{ logs: [], total: N }` 结构）
- 错误处理（各页面增加 try/catch + Toast 提示）
- Loading 状态验证（mock 120ms vs 真实 200-2000ms）

### P1 — 数据层完善：mock → 真实 DB 查询（8 人天）

#### 1.1 数据库 Schema 扩展（2 人天）

需新增表：

| 新表 | 用途 | 模块 |
|------|------|------|
| `mas_routing_config` | 路由引擎配置 | Routing |
| `mas_rate_limit_rule` | 限流规则定义 | Routing |
| `mas_routing_rule_set` | 场景路由规则 | Routing |
| `mas_aggregation_group` | 聚合组 | Routing |
| `mas_elastic_switch` | 弹性切换配置 | Routing |
| `mas_security_event` | 安全事件 | Security |
| `mas_alert` | 告警记录 | Dashboard/Security |
| `mas_guardrail_config` / `mas_guardrail_policy` | 护栏配置/策略 | Security |
| `mas_model_connection` | 模型接入配置 | ModelAsset |
| `mas_eval_result` | 评测结果 | ModelAsset |
| `mas_operation_log` | 操作审计日志 | 全局 |

#### 1.2 DashboardService 真实化（2 人天）

| 方法 | 数据来源 | SQL 策略 |
|------|----------|----------|
| `getSummary` | `mas_call_log` 近 24h 聚合 | `SELECT count(*), sum(prompt_tokens)...` |
| `getTokenSeries` | 按小时分组 | `GROUP BY date_trunc('hour', created_at)` |
| `getDeptTco` / `getAppTcoRank` | 按 app_id 关联部门聚合 | `ORDER BY sum(total_tokens) DESC` |
| 其余 | 暂保留 mock | 标注 TODO |

#### 1.3 RoutingService 真实化（1.5 人天）

配置写入/读取真实 DB 表，重启后配置不丢失。

#### 1.4 SecurityService 真实化（1 人天）

安全事件/护栏策略持久化到 DB。

#### 1.5 MeteringService 补全（1 人天）

`getModelStats`、`listQuotas`、`listMonthlyBills` 基于真实聚合。

#### 1.6 OperationLog 审计日志（0.5 人天）

所有写操作自动记录到 `mas_operation_log`。

### P4 — 安全加固（3 人天）

| 任务 | 验收标准 |
|------|----------|
| 管理端点认证（JWT/Session） | 无有效 Token 返回 401 |
| 操作审计（IP/UA/请求体摘要） | `mas_operation_log` 含完整审计字段 |
| 敏感数据脱敏 | 列表接口不返回 keyFull |
| CORS 收紧 | 非允许 Origin 被拒绝 |
| SQL 注入防护 | 无直接字符串拼接到 SQL |

---
